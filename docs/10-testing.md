# 10. Тесты — не формальность, а способ понять ошибку

Пока движок не написан, `npm test` будет красным. По мере работы тесты начнут проходить. Проверки написаны с помощью **Vitest** и не требуют ни Expo, ни сервера.

~~~bash
npm run check
npm test
npm run demo
~~~

## Чего ждать от тестов

- Бюджет 0 разрешает бесплатные занятия, но запрещает стоимость 1.
- Занятие на 60 минут подходит для 60 минут, на 61 — нет.
- При двух участниках подходит диапазон 1–4, но не 3–5.
- «Неважно» для настроения не начисляет бонус.
- «Другое» не повторяет показанные ID.
- Если список пуст **изначально** — `empty`; если показали всё — `exhausted`.
- Неактивные занятия исключаются всегда.
- Входные массивы нельзя портить через сортировку.

## Пример полноценного теста другой функции

```typescript
import { it, expect } from "vitest";

function afterDiscount(price: number, discount: number): number {
  return price - discount;
}

it("не уходит в минус на обычной скидке", () => {
  expect(afterDiscount(100, 20)).toBe(80);
});
```

В папке `tests/` уже лежат тесты настоящих функций движка. После прохождения всех заданий добавь **собственные** тесты, а не только используй готовые. Лучше всего тестировать границы и пустые случаи.
