# 01. Как программа выбирает занятие

Представь: ты попросил друга предложить, чем заняться вечером. Он не бросает кубик сразу. Сначала спрашивает: **сколько вас, сколько есть времени и денег, где хотите быть**. Затем среди подходящих вариантов ищет те, что больше нравятся.

Программа делает ровно то же, только по понятным правилам.

```text
Каталог (много занятий)
      ↓
Проверка параметров (они вообще имеют смысл?)
      ↓
Жёсткая фильтрация (убираем невозможное)
      ↓
Мягкие предпочтения (каждому оставшемуся начисляем баллы)
      ↓
Сортировка по баллам
      ↓
Выбираем случайно из не более 10 лучших
      ↓
Показываем одну идею + объяснение
```

## Жёсткое и мягкое — в чём разница

**Жёсткое условие:** если у человека только 30 минут, мероприятие на 3 часа предлагать нельзя. При бюджете 0 ₽ платное занятие не подходит.

**Мягкое предпочтение:** человеку нравится творчество. Но прогулка всё равно может оказаться хорошей идеей; просто у рисования будет преимущество в оценке.

Алгоритм без ML называется **правиловым** (rule-based). Для маленького каталога, понятных параметров и учебного проекта он подходит: нет обучения модели, всё объяснимо.

## Маленькая проверка понимания

Три занятия: прогулка (60 минут, бесплатно, улица), настолки (90 минут, 200 ₽, дома), рисование (40 минут, 100 ₽, дома). Пользователь: 45 минут, 150 ₽, дома.

Какое занятие остаётся после фильтрации? Ответ: рисование. Почему настолки не подходят? По времени **и** бюджету.
