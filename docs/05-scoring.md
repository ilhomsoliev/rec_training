# 05. Мягкие предпочтения: как начислять баллы

После жёсткой фильтрации все занятия **возможны**, но одни могут нравиться человеку больше других. Составим простой score.

| Совпадение | Баллы |
|---|---:|
| Настроение | +3 |
| Категория входит в интересы | +2 |
| Есть хотя бы один предпочтительный тег | +1 |
| Длительность укладывается в доступное время с запасом не больше 30 минут | +1 |

Числа — **учебная модель**, не научная истина. В дальнейшем их можно изменить по результатам тестирования. Сейчас они записаны в `SCORING` внутри `src/engine.ts`.

## Считаем на примере

Человек хочет спокойного вечера, любит настолки и имеет 90 минут. Настольная игра на 75 минут совпадает по настроению и категории: 3 + 2 + 1 за близость по времени = 6 баллов. Если совпадёт ещё тег, будет 7.

Вместе с оценкой сохраняй **reasons** — строки с объяснениями, за что начислены баллы. Это поможет UI показать, почему активность предложена.

## Полная функция-пример: оценка блюда

```typescript
type Meal = { name: string; vegetarian: boolean; quick: boolean };
type ScoredMeal = { meal: Meal; score: number; reasons: string[] };

function scoreMeal(meal: Meal, wantsVegetarian: boolean): ScoredMeal {
  let score = 0;
  const reasons: string[] = [];
  if (wantsVegetarian && meal.vegetarian) {
    score += 3;
    reasons.push("Подходит по питанию");
  }
  if (meal.quick) {
    score += 1;
    reasons.push("Быстро готовится");
  }
  if (!reasons.length) reasons.push("Новая идея для обеда");
  return { meal, score, reasons };
}
```

Теперь можешь применить тот же подход к **Activity**. Теги не должны начислять +1 за каждое повторение: **один бонус при хотя бы одном совпадении**.
