# 03. Проверка входных параметров

Прежде чем выбирать, убедимся, что параметры имеют смысл. Если количество участников равно минус двум, результат подбора лучше не показывать — объяснить пользователю ошибку.

В §src/types.ts§ тип §Filters§ уже существует. Все поля перечислены там.

## Полная маленькая функция для примера

Это **не решение** задания: здесь проверяется только количество билетов.

```typescript
function validateTickets(count: number | null): string[] {
  const errors: string[] = [];

  if (count !== null && (!Number.isInteger(count) || count < 1 || count > 6)) {
    errors.push("Выбери от 1 до 6 билетов");
  }

  return errors;
}
```

Обрати внимание: функция собирает массив сообщений. Если ошибок нет, вернёт пустой массив. §Number.isInteger§ полезнее простого §count >= 1§, потому что запрещает 1.5; §Number.isFinite§ ловит §NaN§ и §Infinity§.

Для своего движка проверь:
- участники: §null§ либо целое от 1 до 10;
- время: §null§ либо положительное конечное число;
- бюджет: §null§ либо конечное число от нуля;
- место и настроение: допустимое значение из массивов в §types.ts§ или §"any"§.

Не делай проверку по принципу §if (!budget)§: ноль — допустимая стоимость!
