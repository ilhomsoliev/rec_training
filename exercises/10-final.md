# Финал. Собери свой engine.ts

Теперь у тебя есть все кирпичики. Итог — **полноценный файл `src/engine.ts`**, самостоятельно написанный по урокам.

## Чек-лист результата

- [ ] `validateFilters` проверяет диапазоны, `NaN`, `Infinity`, `null` и `"any"`.
- [ ] `filterActivities` учитывает участников, время, стоимость, место и активность.
- [ ] Настроение и интересы **не** исключают возможные варианты.
- [ ] `rankActivities` начисляет баллы, формирует причины и сортирует.
- [ ] Никакой входной массив не изменяется.
- [ ] `recommend` различает `invalid`, `empty`, `exhausted` и `success`.
- [ ] Уже показанные ID не выдаются повторно в одной серии.
- [ ] Выбор идёт из не более 10 лучших кандидатов.
- [ ] Случайность можно подменить через аргумент `random`.
- [ ] В режиме «Удиви меня» ограничения снимаются, но архивные идеи не выдаются.
- [ ] `npm run check`, `npm test` и `npm run demo` работают.
- [ ] Есть минимум четыре собственных теста и понятный PR.

## Вопросы руководителя

Почему бюджет 0 — не то же самое, что `null`? Почему настроение не должно нарушать ограничение по месту? Чем отличаются `empty` и `exhausted`? Зачем `Set`? Почему тесты используют `() => 0`? Что произойдёт с вариантом на 11-м месте после нажатий «Другое»?

## Усложнения по желанию

Найди способ разнообразить «Удиви меня» при полностью равных score. Проверь качество рекомендаций на новом каталоге. Продумай защиту от повторов между перезапусками, если потребуется реальная история.

**Сдача:** PR в своём fork и короткая демонстрация на 3–5 минут. Не требуется писать мобильный интерфейс, FastAPI или нейросеть: задача — **научиться строить и проверять алгоритм**.
